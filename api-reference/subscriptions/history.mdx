---
title: "Subscription Lifecycle Timeline"
openapi: "GET /v1/subscriptions/{id}/history"
description: "Every recorded status transition and plan switch for a subscription, oldest first — captured by a database trigger so nothing is missed."
keywords: ["subscription history", "lifecycle timeline", "status history", "plan change history"]
---

Returns the subscription's full lifecycle timeline: each **status** transition
(`trialing` → `active` → `past_due` → `paused` / `canceled`) and each **plan**
switch, oldest first. Transitions are captured by a database trigger at the
source of truth, so no change is ever missed — even ones made by background
workers.

Each entry is discriminated by `change_type`:

- `status` — `from_value` / `to_value` are subscription status strings
- `plan` — `from_value` / `to_value` are plan ids

The first `status` row is the creation state, so its `from_value` is `null`.

```json
        "subscription_id": "b9071c55-0e14-4720-80f3-665613ceb7de",
        "change_type": "status",
        "from_value": null,
        "to_value": "trialing",
        "changed_at": "2026-06-01T09:00:00Z"
      },
      {
        "id": "5c7d8e9f-0a1b-4c2d-8e3f-4a5b6c7d8e9f",
        "subscription_id": "b9071c55-0e14-4720-80f3-665613ceb7de",
        "change_type": "status",
        "from_value": "trialing",
        "to_value": "active",
        "changed_at": "2026-06-15T09:00:00Z"
      },
      {
        "id": "7e9f0a1b-2c3d-4e5f-8a6b-7c8d9e0f1a2b",
        "subscription_id": "b9071c55-0e14-4720-80f3-665613ceb7de",
        "change_type": "plan",
        "from_value": "1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d",
        "to_value": "9f8e7d6c-5b4a-4938-8271-605f4e3d2c1b",
        "changed_at": "2026-07-01T09:00:00Z"
      }
    ]

```

<Note>
  Read-only, and derived from a trigger — you can't write to this timeline
  directly; it fills in as the subscription's status and plan actually change. A
  missing or cross-tenant `id` returns `404`.
</Note>
