Recurso emits **ten** event types. Every delivery carries the same envelope; the
object that changed is identified by `object_type` + `object_id`, and its fields
are in `data`.

## Event envelope

```json
{
  "id": "8a1f2b3c-4d5e-4f60-9a1b-2c3d4e5f6071",
  "tenant_id": "b9071c55-0e14-4720-80f3-665613ceb7de",
  "type": "invoice.paid",
  "object_type": "invoice",
  "object_id": "06c151de-8d3a-4b21-9c77-2f0e5a9b4d12",
  "data": {
    "id": "06c151de-8d3a-4b21-9c77-2f0e5a9b4d12",
    "status": "paid",
    "amount_paid": 118000,
    "currency": "INR"
  },
  "created_at": "2026-06-15T08:00:00Z"
}
```

All ids are UUIDs. `data` mirrors the object's current fields; `object_type` and
`object_id` are always present so you can route without parsing `data`.

## The ten event types

| Event | Fires when |
|---|---|
| `invoice.created` | An invoice is generated. |
| `invoice.paid` | An invoice is paid in full. |
| `invoice.payment_failed` | A payment attempt on an invoice fails. |
| `subscription.created` | A subscription is created. |
| `subscription.canceled` | A subscription is canceled. |
| `subscription.renewed` | A subscription renews into a new billing period. |
| `customer.created` | A customer is created. |
| `customer.updated` | A customer's details change. |
| `payment.succeeded` | A payment succeeds. |
| `payment.failed` | A payment fails. |

<Note>
  That is the full set — there are no `subscription.activated`, `.updated`,
  `.past_due`, `payment.refunded`, `invoice.finalized`/`.past_due`, or
  `credit_note.*` / `accounting.*` / `ledger.*` events. If you need finer-grained
  lifecycle history, read an object's status timeline via the API rather than
  waiting on a webhook. The status string uses one L — `canceled`.
</Note>

## Best practices

- **Respond fast.** Return `2xx` quickly and process asynchronously — Recurso
  retries non-`2xx` responses with exponential backoff.
- **Dedupe on `id`.** The same event may be delivered more than once; treat
  `id` as the idempotency key.
- **Verify the signature.** Check the `X-Recurso-Signature` header before
  trusting a payload — see [Verifying webhooks](/advanced/webhooks).
